# Setup and qualification

Use [installation](../../../../docs/startup-and-installation.md) and [installed acceptance](../../../../docs/installed-acceptance.md). Obtain authority for installs, personal configuration changes, live account use and resource mutation.

Build/install an exact immutable candidate and account for old tasks before a controlled runtime upgrade. Configure the installation once, then use one unpinned Codex registration named `passeur` across repositories. Fresh sessions load its tool catalog; old sessions may retain old server namespaces until they exit. Preserve required/optional startup policy, approval settings and unrelated TOML. An installed build is not updated by rebuilding its checkout.

In fresh Codex sessions verify frontend identity, resolved repository/source view, service generation and the submit/wait/input/cancel catalog. A standalone probe does not prove model-callable host attachment. Remove stale named registrations only by exact verified names after inspecting the active config; never delete by prefix. Do not use a substitute task client to bypass human permission. Use explicit service stop/drain for controlled upgrades; frontend disconnect is not service stop.
