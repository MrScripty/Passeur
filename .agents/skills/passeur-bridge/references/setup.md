# Setup and qualification

Use [installation](../../../../docs/startup-and-installation.md) and [installed acceptance](../../../../docs/installed-acceptance.md). Obtain authority for installs, personal configuration changes, live account use and resource mutation.

Build/install an exact immutable candidate, account for old tasks and close old connection-owned hosts normally. Explicitly migrate profile1/2 to3 with backup, then update the existing named server binding. Preserve required/optional startup policy, approval settings, profile/state paths and unrelated TOML. An installed build is not updated by rebuilding its checkout.

In fresh Codex sessions verify status2 frontend identity, service generation and the new submit/wait/input/cancel catalog. A standalone probe does not prove model-callable host attachment. Do not use a substitute task client to bypass human permission. Use explicit service stop/drain for controlled upgrades; frontend disconnect is not service stop.
