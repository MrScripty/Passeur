## Subscription credential lifecycle discovered before any account use

The user reports a Codex subscription login, with no separately supplied API credential. The installed CLI reports 0.157.1. [OpenAI's CI/CD auth guidance](https://learn.chatgpt.com/docs/auth/ci-cd-auth) instructs operators to use one cached `auth.json` per runner or serialized stream, retain refreshed credentials, and avoid concurrent reuse of a copied login because rotation can break another user of that cache. This is relevant even when the host's original file is never modified: a disposable guest copy could use the same refresh token against the auth service, rotate it, and then discard the replacement. The existing personal login has not been read or copied.

The [tagged 0.157.1 auth manager](https://github.com/openai/codex/blob/rust-v0.157.1/codex-rs/login/src/auth/manager.rs) makes the risk concrete. `auth()` checks whether a ChatGPT access token expires within five minutes (or whether an unparseable token was last refreshed over eight days ago), then calls `refresh_token()` before returning; unauthorized recovery also has a refresh step. The refresh path posts to `https://auth.openai.com/oauth/token` and persists replacement tokens in its active auth storage. Thus `account/read` with `refreshToken:false` cannot certify that a later model turn avoids refresh. A future live route needs an enforced no-refresh egress policy with version-matched checks and a fail-closed 401/expiry result, or a separately owned persistent login lifecycle.
