# Composed-design admission

Applicability: **applicable**. These are the current eight Architecture probe answers for the complete code-only artifact.

## 1. Independent concerns and their dimensions

Execution supervision owns *what* happens to an admitted native assignment, *who* may control it, *how* adapter evidence is interpreted, *when* it can settle, *where* its resources live, and *why* safe lifetime is preserved; its existing coordinator/adapters remain authoritative.

Structural observation owns *what* exact source syntax differs, *who* produced/exposed the observed workspace, *how* capture/parse/matching occur, *when* a observation is current, *where* source ranges belong, and *why* bounded evidence is useful. Its output neither authorizes nor changes execution.

Coordination control owns parent/work/target associations, explicit notes and one case leader; its lifetime is independent of a parser job or client connection. Git owns committed content/history. The store owns publication mechanisms. Transport owns validated projection and connection wait lifetime. No record becomes canonical for all these concerns merely because it serializes references to them.

## 2. Necessary versus accidental interleavings

Necessary: report bytes with their captured source identity; case leadership with generation/idempotency; workspace identity with write-participant registration; task-admission identity with its announcement linkage; resource retirement with active case references; current disclosure policy with every output.

Independent invariants: parser results carry source facts only; native liveness follows execution evidence; notifications never change task phase; Git alone identifies code versions; parent permissions are checked at disclosure rather than stored in syntax caches; integration remains parent-owned.

No clock determines ownership or task completion. Observation intervals schedule reads. Analyzer cancellation applies only to pure computation. Version roles are distinct: source OID/digest, parser/extractor identity, public/IPC schema, store version, control generation, observation cursor epoch, and existing native generation.

## 3. Caller and composition-root knowledge

A parent knows its ordinary task, source view/base, optional relevant watches, and target. It need not manage syntax node IDs, parser allocations, proposal families, model summaries or SQLite transactions. A detailed report request takes an evidence/work reference rather than requiring reconstruction of a query graph.

The composition root binds the existing runtime, coordination store, source observer, installed parser helper and public projection. It knows their lifetime/capacity interfaces, not per-language node names or note interpretation. Native adapters retain their own lifecycle contract and do not import syntax extraction or graph code.

## 4. Representative changes and forced owners

Changing Kotlin parameter syntax affects its extractor/query, pinned grammar if needed, language fixtures and bundle evidence—not task control or note schemas. Changing report range encoding affects capture/extraction boundary, report schema/renderer and consumers. Changing a notification rule affects the relevance owner, its policy representation and rule tests, not grammar parsers. Changing parent handoff affects coordination authorization/persistence/UI/CLI elicitation, not Git diff logic. Changing a provider's stop evidence remains in native lifecycle consumers, except any actual source-observation attach/detach consequence. Switching the parser backend changes helper packaging/protocol qualification and performance evidence, not the parent workflow.

## 5. Stable interfaces and hidden knowledge

Use validated captured-source and extraction-result contracts. Source roles/digests and coverage are visible because callers need them; native tree objects, binding handles and grammar node names stay inside analysis. Coordination consumers see typed case transitions, not aggregate JSON layout. Shared helper transport reuses framing only; it does not centralize unrelated semantic versions. Git helpers expose exact operations and errors, not hidden current-HEAD defaults. Report cached values carry no ambient authorization.

## 6. Independent evolution, testing, failure and replacement

Parser failure yields observation incompleteness and leaves known native tasks running. Coordination-store failure blocks new coordination-control changes but preserves independent existing execution evidence. Source reads can fail per file without inventing a clean comparison. Transport loss detaches a waiter, not its work. Language tests run without agents, compilers or project builds. Actual host/native qualification is still required for lifecycle/user-path claims. Replacement of JSON with another store would preserve the coordination transition contract and require new durability evidence, not a task rewrite.

## 7. Deletion test for permanent mechanisms

| Mechanism | If removed | Decision |
|---|---|---|
| Git endpoint/capture roles | Callers must guess which versions a diff describes | Retain; this is essential evidence identity |
| Tree-sitter helper and qualified extractors | Each parent receives raw diffs or reimplements multilingual parsing; blocking native work risks supervision | Retain established parser in isolated owner |
| Parser manifest | Artifact/query/ABI drift becomes untraceable and nonreproducible | Retain one build-owned manifest, not parallel catalogs |
| Conservative matcher | Callers reconstruct declaration correspondence or receive misleading matches | Retain bounded product-specific matching, not semantic resolver |
| Relevance/cursor owner | Every change becomes a model interrupt or relevant updates disappear silently | Retain small deterministic rules and gap-aware retrieval |
| Work/announcement metadata | Direct hosts and pre-start overlap cannot be associated reliably | Retain small records; reuse task identity whenever it exists |
| Notes and target leadership | Parents cannot publish attributed agreements or prevent duplicate cooperating reconciliation | Retain narrow optional operations |
| Atomic control aggregate | Coordinated updates lose revisions/claims or each caller owns recovery | Retain existing proven publication primitive; no custom database |

## 8. Necessary complexity and cumulative result

The retained cost is multilingual syntax qualification, coherent source identity under concurrent edits, bounded caching/notification, small cross-parent authority records, and installed native-helper packaging. These directly enable Passeur's reporting and coordination responsibilities. Thirteen language/dialect extraction paths, especially C/C++ and Svelte, require material verification; performance claims depend on representative measurement.

The plan keeps one service and scheduler, one analysis helper initially, one narrow coordination authority, existing atomic storage, and a built-in parser catalog justified by thirteen current requirements. It has no semantic graph store, compiler, mutation-application engine, publication ref, general rule interpreter or autonomous reconciler. Re-run admission if measured call-site knowledge, state interleaving or permanent machinery exceeds this description.

## F0/F1 composition check

The eight-probe target admission remains prospective. This increment keeps its native-independent boundaries: exact source reads belong to observation; matching and rendering consume internal extracted values; materiality is a pure function, not another scheduler/store. The real parser/helper and all coordination protocol owners remain unimplemented. No parser package, new dependency, public command or persisted record is introduced. Future native integration must establish its current decoder/packaging contract rather than infer it from these test fixtures.

The accepted task stays active during workspace-hook execution; its durable creation intent is published under the existing short administration guard. Only the hook-bearing Git operation leaves that guard. Stable collection receives a signal-free view after confirmed stop while preserving repository authority and the original execution result. These are lifetime corrections, not alternate execution modes.
