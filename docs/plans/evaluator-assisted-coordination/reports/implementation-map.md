# Implementation map and exact write ownership

This report owns the planned production/test file inventory. All `src/observation/`, `src/coordination/`, and structural fixture paths below are **new proposed paths**, not claims about existing code. Existing paths are from the examined Passeur source. M0 verifies current placement and the reachable consumer inventory before editing. A directly affected additional file is recorded first; a changed authority, scope, risk or acceptance boundary requires re-planning.

The listed module split is based on independently changing concerns. It does not require a class per file or public API per noun. Consolidate a nominal wrapper when it adds no owned invariant, recording the placement change. Every slice also updates its directly affected plan/ledger/issues/evidence, without mirroring commit cadence.

## Shared administrative ownership

One lead owns all public/persisted schema changes, service composition, configuration, package locks, generated parser manifest, shared fixtures, migration, plan status and integration. New parser artifacts are generated by a reviewed build procedure; production binary outputs are not hand-edited. Reference documentation and tests are updated with their canonical source.

`AGENTS.md` remains a route, not a mechanism that picks this plan automatically. Implementation is explicitly invoked with the canonical plan path and operation.

## Parallel implementation contract

M0 and M1 shared contracts are serial. After M1 admission stabilizes, workers may own disjoint language extractor/query/fixture stems; the lead owns catalog, generated manifest and package dependencies. Each worker's handoff lists its exact base/result, primary paths, adjacent permitted tests, forbidden shared files, oracle decisions and remaining support limits. Requiring a shared-schema change is an escalation, not permission to independently redefine it. Integrate serially and re-run affected shared/range/bundle evidence.

The actual workflow selects Concurrent Plan Integration only if outstanding authorizing proposals can become stale against mutable plan/shared authority. It is not selected merely because Passeur itself supports concurrent agents. No worker cleans up other workers' branches/worktrees or bypasses ordinary hooks.
