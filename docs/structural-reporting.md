# Structural reports (completion candidate)

Structural observation reads declared source for an active work record. The current source owner issues explicit grants through `passeur_work` (`grant_source`); ordinary metadata readers receive no source access. A `report` grant permits compact reports and notices, while `detail` also permits retained source excerpts. `watch_source` selects exact recipient regions and optional exact-file dialect overrides. The owner may replace either list with an empty list to revoke it. Sharing, closure and metadata adoption clear grants and watches. Notes, case leadership and agreement acknowledgment never supply source authority. Current ownership and work revision are checked again on retrieval, including notice pull and acknowledgment. Managed-task adoption invalidates earlier source authority.

Use `passeur structural-report --project PATH --work UUID` or `passeur_structural_report` for an on-demand report; use `passeur structural-refresh --project PATH --work UUID` or `passeur_structural_refresh` to reconcile monitored work. The request carries a work ID, never an arbitrary path. The service resolves the recorded workspace and exact input commit, captures current working content, and compares the two through its native analysis child. Each work retains its own INPUT and OBSERVED source identity. Attribution means observed in that work, not sole authorship or compatibility. Different input bases remain separate pairs; cross-task correspondence requires the same immutable input declaration. A report gives written declarations and direct syntax changes, with body/default changes represented by markers rather than their values. Ambiguous matches, parser damage, absent or unreadable content and coverage limits are reported explicitly.

The candidate dialect routes are Rust (`.rs`), TypeScript (`.ts`, `.mts`, `.cts`, `.svelte.ts`), TSX (`.tsx`), JavaScript (`.js`, `.mjs`, `.cjs`, `.svelte.js`), JSX (`.jsx`), Python (`.py`, `.pyi`), Lua (`.lua`), Kotlin (`.kt`, `.kts`), Zig (`.zig`), C# (`.cs`), C (`.c`), C++ (`.cc`, `.cpp`, `.cxx`, `.hpp`, `.hh`, `.hxx`), Odin (`.odin`) and Svelte 5 (`.svelte`). Ambiguous `.h` requires an exact `c` or `cpp` override; `.js` containing JSX requires an exact `jsx` override. Explicit overrides belong to a watch, not an inferred repository policy. A parser result does not prove complete extraction, and reports make no semantic safety or urgency judgment.

The on-demand response contains up to four file reports with `report_id`, dialect and text, plus limitations. The same currently authorized owner can read an exact retained range with `passeur structural-detail --project PATH --work UUID --report UUID --side input|observed --start-byte N --end-byte N` or `passeur_structural_detail`. Ranges are half-open UTF-8 byte intervals, at most 8192 bytes, and end at code-point boundaries. Detail uses captured bytes rather than rereading a changed path. The process retains at most 32 captured pairs and 64 MiB; eviction, restart, revised authority, and absent source sides return an explicit unavailable result.

The service monitors declared and watched areas with bounded filesystem watchers, a quiet interval and a reconciliation sweep. Events trigger recapture; they are not an authoritative edit log. Routine notices require changed evidence in an explicit watched region; correspondence notices can report overlap or resolution for the same immutable-input declaration across tasks. `passeur structural-notice-pull --project PATH [--cursor N]` or `passeur_structural_notice_pull` returns unacknowledged notices. Pulling does not consume them. A pruned cursor returns a gap and current snapshot. A caller explicitly acknowledges one notice using `passeur structural-notice-ack --project PATH --notice SHA256` or `passeur_structural_notice_ack`. `passeur structural-current --project PATH` / `passeur_structural_current` lists current report identities. `passeur structural-artifact-report --project PATH --artifact SHA256` / `passeur_structural_artifact_report` retrieves a compact retained report. `passeur structural-artifact-detail --project PATH --artifact SHA256 --side input|observed --start-byte N --end-byte N` / `passeur_structural_artifact_detail` reads an authorized byte range from that artifact. Artifact publication precedes notice publication. A notice is an observation for a parent to inspect, not an automatic model turn or worker instruction.

Observation uses one active helper job, a queue of four, bounded messages, source, watchers, reports and notices. The service reads `PASSEUR_OBSERVATION_MONITOR=on|off` at construction; `off` suppresses automatic watching while explicit report and refresh remain available. On supported Linux, the analysis child's sampled RSS has a 512 MiB ceiling; overload can defer or report analysis incomplete. Resource limits affect the analysis child only. Native task admission, control, input, cancellation and resource ownership remain with their existing owners. External work may be observed while the service runs and on explicit refresh; a disconnected last client need not keep an external editor's observer alive. Reattachment reconciles missed changes. The completion plan's [verification record](plans/structural-coordination-completion/reports/verification-and-release.md) owns final native, installed, resource and real-host acceptance claims.
