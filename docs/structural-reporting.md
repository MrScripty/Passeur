# Structural reports (development candidate)

The current candidate has an owner-only, on-demand report for active registered or enrolled work. The work must declare a `file` or `subtree` area containing `.rs`, `.ts`, `.mts`, `.cts` or `.tsx` source. Use `passeur structural-report --project PATH --work UUID` from the work owner's existing authenticated identity, or `passeur_structural_report` from the same authenticated parent. The request contains a work ID, not a filesystem path. The service resolves the recorded worktree, reads the work's exact input commit and samples current working files, then compares real native Tree-sitter extractions in a separate analysis child. A report identifies both source roles and says only that the observed difference occurred in this work; it does not assign exclusive authorship or assess compatibility.

The initial extractor covers Rust/TypeScript/TSX functions, Rust trait/impl/module scopes, structs/aliases/enums, and TypeScript named arrows, overloads, interfaces/classes/aliases/enums with direct fields and methods. It presents written parameters, return annotations and direct type syntax, masks parameter defaults, field initializers, enum values, header attributes and comments, and marks body or concealed-header changes without presenting their values. Unmapped syntax, parser damage and incomplete headers are reported as limitations. The bounded inventory samples at most four declared files per request and reports truncation. Metadata readers are denied source reports; metadata sharing is not source-evidence permission.

Each returned file report has a `report_id`. The same owner can request an exact captured byte range with `passeur structural-detail --project PATH --work UUID --report UUID --side input|observed --start-byte N --end-byte N` or `passeur_structural_detail`. A detail request reads the retained captured bytes, never the current path. The current process keeps at most 32 captured pairs and 64 MiB of source bytes; eviction, restart, a closed or changed work record, and non-present source sides return an unavailable result. Detail ranges are at most 8192 bytes and must end on UTF-8 boundaries.

This candidate does not yet persist reports or captures across service restarts, monitor edits continuously, deliver notices, support source-evidence grants, or cover the other required languages. Its diagnostic builder can package the pinned native artifacts, but a final installed candidate and installed public workflow have not been qualified. Repeating a request samples a new working capture; after eviction or restart it cannot recover an earlier working sample. The completion plan keeps those acceptance claims open until the native/public/installed and real-host procedures pass.
